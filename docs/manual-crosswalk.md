# Crosswalk: ADRs, the threat model and the red-team tests

Which Chaperone ADR answers which threat of the threat model in the shared spec repository (`factory-spec`, not yet public, file `security/threat-model.md`, tag **v0.1.0**), and which red-team id (`security/red-team.md` in the same repository) tests it, with where Chaperone runs that test (`test/redteam/doc.go` is the source for coverage). Threat ids are `TB<boundary>-<S|T|R|I|D|E><n>`; boundaries: TB1 VM and host, TB2 sandbox and proxy (both belong to the runner, a separate project that starts agent runs and is not public yet; its work is Phase 2), **TB3 Chaperone and agents**, **TB4 Chaperone and GitHub or Google**, **TB5 Chaperone and the approver**.

Limits of this page: only rows of the threat model that Chaperone's ADRs answer are listed; the rows read in full are TB1, TB2, TB4, TB5 and TB3-S1, E4 and E5; other TB3 rows are cited through their RT ids only. There is no column for **Agent Baseline** controls. Neither the threat model nor this repository names control ids for that paper (it is cited as a source only), so such a column would have to be invented.

Coverage words follow `doc.go`: **covered** (an offline replay with a baseline and a mutation check where noted), **partial**, **not offline** (needs the server or another account: a rehearsal checklist item), **not covered**.

## Threat ids that no ADR here answers

TB1 and TB2 rows (VM, sandbox, proxy) belong to the runner (RT-34 to RT-49 are Phase 2 gates). TB4-D1 (provider limits: fail closed) is answered by the op pipeline, not an ADR (RT-31: not covered here). TB4-E2 for self-hosted CI runners stays High until a later stage.

## Merging by hand and the ledger

A merge that a person does by hand, with their own GitHub login, bypasses the TB4-T1 and TB4-T2 controls (RT-01 to RT-03) and leaves no ledger event. A comment on the pull request is the only record. That is a known cost, not a gap in a test.
